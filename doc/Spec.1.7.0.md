## 1. 목적

1.7.0의 작업은 두 가지다.

1. **CS-01 CLIP STUDIO PAINT(이하 CSP) 브러시 필압 감각 연구.** SUT 브러시로 그릴 때
   손에 느껴지는 필압 반응을 CSP와 같게 맞춘다. 굵기 수치가 같아도 "느낌"이 다르면
   완료로 보지 않는다.
2. **WN-01 각 창을 macOS 방식의 독립 OS 창으로 띄우기.** 패널과 대화상자를 메인 창 안에
   그린 영역이 아니라 각각의 운영체제 창으로 띄워, macOS 앱처럼 메인 창 밖으로 꺼내고
   다른 모니터로 옮길 수 있게 한다. Windows에서도 같은 구조로 동작한다.

두 작업은 서로 의존하지 않으므로 병렬로 진행할 수 있다.

## 2. CS-01. CSP 브러시 필압 감각 연구

### 2.1 현재 기준선

- 2026-11-14 G펜 비교(합성 펜, 필압 0 → 1 → 0, 손떨림 보정 6, 속도 보정 켬):
  필압 응답은 CSP와 같은 선형이며 단위 필압당 약 24.9 px로 일치한다. 다만 Prism 획이
  필압과 무관하게 1.6–1.9 px 더 굵다. 원인은 필압 곡선이 아니라 팁 가장자리·안티앨리어싱
  렌더링 차이다.
- SUT의 독립 필압 곡선(최솟값 + 응답 곡선)은 읽고 적용한다
  (`docs/sut-analysis.md` › independent pressure responses).
- 측정하지 않은 것: 기울기, 다른 속도에서의 속도 보정, G펜 외 서브 도구, 불투명도·농도 필압,
  실제 태블릿의 약한 시작과 빠른 연속 획.
- CSP의 전역 필압 감도 설정(파일 › 필압 검출 레벨 조절)과 서브 도구별 필압 곡선이
  겹칠 때의 순서는 아직 확인하지 않았다.

### 2.2 연구 항목

| ID | 항목 | 확인할 것 |
|---|---|---|
| CS-01a | 전역 필압 감도 | CSP 필압 검출 레벨 곡선의 저장 위치·형식, 서브 도구 곡선과의 적용 순서 |
| CS-01b | 필압 → 크기·불투명도·농도 | 서브 도구 10종 이상(G펜, 둥근 펜, 연필, 수채, 에어브러시 등)에서 필압 단계별 굵기·농도 측정 |
| CS-01c | 시작·끝 반응 | 약한 필압 시작, 획 끝 꼬리, 입·출 처리(입력 시작·끝 효과)의 길이와 모양 |
| CS-01d | 속도·손떨림 보정과의 상호 작용 | 속도 보정 켬/끔, 보정 0·6·20·50에서 필압 지연과 획 모양 |
| CS-01e | 팁 렌더링 굵기 차이 | 같은 크기에서 1.6–1.9 px 차이를 만드는 가장자리·안티앨리어싱 규칙 |
| CS-01f | 기울기 | 기울기 → 크기·불투명도·각도 응답 |
| CS-01g | 필압 샘플 보간 | 입력 샘플 사이 필압 보간 방식과 찍힘 간격의 관계 |

### 2.3 방법

- 같은 합성 획을 CSP와 Prism에 넣는다. macOS·Windows 모두 `pen-pressure-test` 스킬의
  `pen_inject`로 주입하고 `ui.penTrace`로 확인한다. CSP는 Tablet PC(Windows) 입력으로
  두고, 측정 뒤 원래 설정으로 되돌린다.
- 측정값(열별 커버리지 합으로 구한 굵기, 농도 단면)을 `docs/pen-input-validation.md`에
  날짜별로 기록한다. 원본 SUT 파일과 CSP 설정 파일은 바꾸지 않는다.
- CSP 내부 분석이 필요하면 2026-10-15 승인 범위(SUT·브러시 처리와 직접 관련 자원,
  읽기 전용 분석, 독립 구현)를 지킨다. 원시 분석 자료는 저장소 밖에 둔다.
- 실제 태블릿으로 최종 체감 확인을 한다. 합성 펜 결과만으로 "느낌이 같다"고 판정하지 않는다.

### 2.4 예상 수정 위치

`crates/io/src/sut/`(필압 곡선·효과 읽기), `crates/paint/src/dynamics.rs`,
`crates/paint/src/render.rs`(팁 가장자리), `crates/paint/src/brush.rs`,
`crates/tablet`(샘플 보간이 원인일 때만).

### 2.5 완료 조건

- 측정한 서브 도구 전부에서 필압 단계별 굵기 차이가 0.5 px 이내, 농도 차이가 2/255 이내다.
- 약한 시작과 끝 꼬리 길이가 CSP와 5% 이내로 일치한다.
- ABR(Photoshop) 브러시의 필압·꼬리·pulled-string·catch-up 회귀 검사에 새 차이가 없다.
- 실제 태블릿으로 그린 획을 CSP와 나란히 놓고 사용자가 차이를 느끼지 못한다.
- 결과와 남은 차이를 `docs/pen-input-validation.md`와 `docs/roadmap.md` › Honest parity
  assessment에 날짜와 함께 기록한다.

## 3. WN-01. 각 창을 macOS 방식의 독립 OS 창으로 띄우기

### 3.1 현재 상태

- 문서 창은 이미 독립 OS 창으로 떼어 낼 수 있다(`doc_windows.rs`, Float in Window).
- 파일 › 새로 만들기 등 일부 대화상자는 `floating_window.rs`의 `show`/`show_titled`로
  OS 창에 뜬다. `show_titled`는 macOS에서 시스템 제목 표시줄(신호등 버튼, 둥근 모서리)을 쓴다.
- 반면 떠 있는 패널 창(`dock_float.rs`)은 메인 창 안의 `egui::Area`다. 메인 창 밖으로
  나갈 수 없고, 다른 모니터로 옮길 수 없으며, 떼어 낸 문서 창 뒤에 가려질 수 있다.
- `egui::Window`로 메인 창 안에 그리는 대화상자도 아직 10개 파일에 남아 있다.

### 3.2 요구사항

- **떠 있는 패널.** 탭이나 그룹을 떼어 내면 독립 OS 창(egui viewport)이 된다. 메인 창 밖과
  다른 모니터에 둘 수 있다. 크기 조절, 접기, 아이콘 모드, 다시 도킹(탭 줄·가장자리에 놓기)은
  지금과 똑같이 동작한다.
- **대화상자.** 모든 대화상자는 `floating_window`를 거쳐 OS 창으로 띄운다. 모달은 원래 창 위
  가운데에 열고, 떼어 낸 문서 창 뒤에 가려지지 않는다.
- **macOS 모양.** macOS에서는 시스템 제목 표시줄과 동작을 따른다. 패널 창은 유틸리티(패널)
  창 수준으로 메인 창 위에 뜨고, Prism이 백그라운드가 되면 함께 숨거나 일반 쌓임 순서로
  돌아간다(Photoshop for Mac과 같은 동작). 테마의 밝은·어두운 외관을 따른다.
- **Windows.** 같은 구조의 독립 창으로 동작한다. 제목 표시줄은 Prism 테마의 자체 표시줄을 쓰고,
  작업 표시줄에 패널 창이 따로 늘어나지 않게 한다.
- **포커스와 단축키.** 패널 창에 포커스가 있어도 전역 단축키(도구 전환, 실행 취소 등)가
  메인 문서로 전달된다. 텍스트 입력 칸에 포커스가 있을 때만 예외다.
- **저장과 자동화.** 각 OS 창의 위치·크기·모니터를 `UiState`와 작업 영역에 저장한다.
  모니터가 사라졌으면 보이는 화면 안으로 옮긴다. 제어 채널과 MCP에서 창 목록을 읽고
  띄우기·도킹을 명령으로 할 수 있다.
- **헤드리스.** OS 창이 없는 환경(스냅숏 예제, 테스트)에서는 지금처럼 메인 컨텍스트에 그린다.

### 3.3 구현 순서

| 단계 | 내용 | 선행 조건 |
|---|---|---|
| A | `egui::Window` 대화상자를 `floating_window`로 옮기기 | 없음 |
| B | 떠 있는 패널 그룹을 viewport로 그리기, 패널 상태 공유 | A의 창 수명·포커스 처리 |
| C | OS 창 사이 끌어서 도킹·떼어 내기(창 밖 드롭 포함) | B |
| D | macOS 창 수준·백그라운드 동작, Windows 작업 표시줄 처리 | B |
| E | 작업 영역 저장·여러 모니터 복원, 제어 채널 명령 | B–D |

### 3.4 예상 수정 위치

`crates/ui-egui/src/dock_float.rs`, `dock_drag.rs`, `dock_model.rs`, `floating_window.rs`,
`doc_windows.rs`, `state.rs`, `shortcuts.rs`, `control.rs`, `egui::Window`을 쓰는 대화상자 파일들,
macOS 창 수준 처리가 필요하면 `crates/tablet`과 같은 격리 원칙을 따르는 별도 경계(새 `unsafe`는
승인 없이 추가하지 않는다).

### 3.5 완료 조건

- 모든 패널을 메인 창 밖·두 번째 모니터로 떼어 내고 다시 도킹할 수 있다.
- 남은 `egui::Window` 대화상자가 0개다.
- 떼어 낸 문서 창이 패널·대화상자를 가리지 않는다.
- 재시작 후 패널 창이 같은 위치·크기·모니터에 다시 열린다.
- 패널 창에 포커스가 있어도 단축키가 동작한다.
- 패널 창을 열고 닫거나 끌어도 캔버스 프레임 속도가 떨어지지 않는다(창마다 매 프레임 전체 다시
  그리기 금지, 바뀐 창만 다시 그리기).
- macOS와 Windows에서 스크린숏으로 확인하고, `docs/ui-design.md`의 창·도킹 설명을 갱신한다.
