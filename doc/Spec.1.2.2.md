## 1. 목적과 완료의 의미

ABR 브러시는 Photoshop의 보정·필압·찍힘·색상 동작을 따르고, SUT 브러시는
CLIP STUDIO PAINT(이하 CSP)의 보정과 브러시 옵션을 따른다. 두 방식의 설정이
서로 섞여 필기감이 바뀌지 않아야 한다.

SUT 옵션의 지원은 다음 여섯 단계를 모두 충족해야 한다.

1. 원본 값을 정확하게 읽는다.
2. 가져온 값과 의미를 보존한다.
3. 사용자와 에이전트가 값을 조회하고 수정할 수 있다.
4. 수정한 값이 실제 그리기에 반영된다.
5. 프리셋 저장·재시작·재선택 후에도 값과 동작이 유지된다.
6. CSP의 대응 옵션과 결과를 비교해 차이를 검증한다.

가져오기 성공, 경고 없음, 옵션 표시, 빈 획이 아님은 각각 중간 지표다.
이들만으로 원본 호환 완료를 선언하지 않는다. 기존 ABR 동작을 보존하는 회귀
검사와 실제 Photoshop에 가까운지를 판단하는 비교 검사는 별도로 수행한다.

## 2. 대상 소재와 현재 기준선

프리즘의 CLIP STUDIO 패널은 CSP가 PC에 저장한 소재 목록과 도구 설정을 읽는다.
2026-11-03에 확인한 동일 저장소의 구성은 다음과 같다.

| 분류 | 개수 | 본 명세에서의 처리 |
|---|---:|---|
| 브러시 | 154 | SUT 렌더링·보정·옵션 호환성 전수 검사 대상 |
| 기타 보조 도구 | 2 | 브러시와 분리하여 해당 도구의 가져오기·사용 검사 |
| 이미지·레이어 소재 | 288 | 소재 가져오기 회귀 검사 대상으로 별도 집계 |
| 전체 | 444 | 패널의 ‘모두 444’와 일치 |

수정 전 기준선은 156개 도구 소재 가져오기 성공, 154개 브러시의 비어 있지 않은
시험 획 생성, 보고된 가져오기·획 오류 0건, 경고 소재 47개·총 60건이다.
종료 보정 수정까지 반영한 최종 재검사에서도 156개 도구 가져오기와 154개 브러시
획 생성이 성공했고 오류 0건을 유지했다. 경고는 **39개 소재·51건**으로 줄었다.
초기 감사에서 132개 소재에 편집 컨트롤이 없는 표시 항목 ID 안내가 있었으며,
이 옵션 편집 범위는 아직 전수 해결하지 않았다.

기존 시험은 8비트 RGB, 흰 배경, 하나의 필압 경로, 고정 난수 시드를 사용하고
브러시 크기를 최대 40px로 제한한다. CSP와의 비교 결과가 아니며 실제 크기,
색상 배경, 전체 옵션, 태블릿 입력, 다른 비트 깊이의 호환성은 아직 입증하지 않았다.

## 3. 범위와 구현 순서

| 단계 | 요구사항 | 우선순위 | 선행 조건 |
|---|---|---|---|
| A | BR-01 보정 경로 분리, BR-02 저장·전환 | P0 | 기존 동작 재현 및 ABR 기준선 확보 |
| B | BR-03 CSP 색상 평가 | P0 | 브러시 동작 계열 식별 |
| C | BR-04 손떨림·후 보정 | P1 | 보정 경로 분리, CSP 추가 분석 |
| D | BR-05 입자·단위, BR-06 혼합, BR-07 이중 브러시, BR-08 기타 효과 | P1 | 기능별 원본 의미 확인 |
| E | BR-09 전체 옵션 편집과 명령 지원 | P1 | 옵션 목록 작성은 A와 함께 시작; 반영은 각 기능 구현과 함께 수행 |
| F | QA-01 전수 비교와 회귀 검사 | 필수 | 비교 도구는 A부터 준비, 최종 판정은 A–E 이후 |

이번 작업에서 CSP 계정 로그인·온라인 다운로드 시스템을 새로 만들지 않는다.
소재 원본은 변경하지 않으며, 보조 도구와 레이어 소재를 브러시 성공률에 포함하지 않는다.
모든 SUT 옵션 지원은 최종 목표다. 현재 154개가 사용하지 않는 옵션도 목록에서
누락하지 않고 구현·미구현·검증 대기 상태를 명시한다.

## 4. 기능별 수정 명세

### BR-01. ABR/SUT 보정 경로 분리

**현재 문제:** `BrushSettings::picked_over`가 이전 도구의 Photoshop식 매끄럽게를
무조건 유지하고, `dynamics.rs`가 CSP 보정 이후 다시 `Smoother`를 실행한다.
세션 기본 매끄럽게는 10%다. SUT 손떨림 보정이 0이어도 추가 보정이 적용될 수 있다.

**요구사항**

- 원본 계열 또는 명시적 동작 프로필로 Photoshop/CSP 보정 정책을 선택한다.
- `csp_stabilizer` 존재 여부만으로 SUT를 판별하지 않는다. 손떨림 보정 0인 SUT도
  CSP 계열로 유지한다.
- ABR은 Photoshop식 매끄럽게와 관련 옵션을 사용한다. SUT는 CSP 손떨림·속도 보정과
  후 보정 설정을 사용하며 Photoshop식 매끄럽게를 암묵적으로 덧붙이지 않는다.
- 입력 수집, 실시간 표시, 펜을 뗀 뒤 처리, 시작·끝 효과의 경로 계산에서 같은 정책을 사용한다.
- 기본 브러시·사용자 제작 브러시·구형 프리셋의 동작 정책을 명시하고, 불명확한
  출처를 임의로 SUT로 분류하지 않는다.

**예상 수정 위치:** `crates/paint/src/brush.rs`, `dynamics.rs`,
`crates/engine/src/brush_cmds.rs`, `preset_import_cmds.rs`, 프리셋 선택 경로.

**완료 조건**

- ABR → SUT → ABR 전환 후 각 계열의 설정이 복원된다.
- 이전 ABR 매끄럽게가 0/10/100% 중 무엇이든 같은 SUT 입력의 결과는 동일하다.
- SUT 보정 0은 CSP에서 비활성화된 보정에 해당하며 숨은 Photoshop 필터가 실행되지 않는다.
- 같은 계열·입력의 실시간 미리보기와 확정 획이 의도한 종료 처리 외에는 일치한다.
- 기존 ABR 필압·꼬리·pulled-string·catch-up 회귀 검사에 새 차이가 없다.

### BR-02. 프리셋 상태와 저장 호환성

- 계열, 보정 설정, CSP 옵션을 직렬화하고 저장 후 읽었을 때 의미를 유지한다.
- Photoshop의 도구 단위 매끄럽게와 SUT의 프리셋별 보정 설정의 소유 범위를 분리한다.
- 기존 SUT 메타데이터로 확실하게 식별할 수 있는 프리셋은 이행한다. 이미 유실된
  원본 옵션은 복원했다고 주장하지 않고 재가져오기 필요 여부를 알린다.
- 새 필드는 하위 호환 기본값을 제공한다. 기본값이 기존 ABR 동작을 바꾸지 않아야 한다.
- 프리셋 복제·이름 변경·다른 그룹 이동·재가져오기·재시작 경로에서도 계열이 유지된다.
- 문서 모델 필드를 추가하게 되면 `prism-format` 저장·복원과 해당 PSD 매핑도 검토한다.

**예상 수정 위치:** `crates/paint/src/brush.rs`, `sut.rs`,
`crates/engine/src/preset_store.rs`, `preset_store/`, `brush_preset_cmds.rs`.

**완료 조건:** 구형 프리셋 읽기와 새 프리셋 왕복 테스트, 계열 전환 후 저장·재실행
테스트가 통과하며 원본 CSP 소재 파일은 변경되지 않는다.

### BR-03. CSP 색상 평가와 일정한 보조색 혼합

**현재 문제:** `io/src/sut/blend.rs::jitter`는 난수 입력이 없는 색상 변화를 0으로
버린다. 첨부된 `葉っぱブラシ3`의 경고를 재현했으며, 일정한 보조색 혼합 누락은
11개 소재에 영향을 준다.

**요구사항**

- CSP용 색상 설정·평가를 마련하고 Photoshop Color Dynamics의 난수 폭에 모든 값을
  억지로 맞추지 않는다. 공통 계산은 의미가 일치할 때만 공유한다.
- 난수 입력이 꺼진 경우에도 활성화된 일정한 색상 변화와 보조색 혼합을 적용한다.
- 색상·채도·명도 변화의 부호, 한쪽으로 치우친 난수 범위와 입력 곡선을 보존한다.
- 획 단위와 브러시 팁 단위 변화를 함께 활성화할 수 있도록 적용 시점을 구분한다.
- 주색·보조색 대상 선택, 혼합 순서, 색상 공간, 범위 제한을 CSP 근거로 확정한다.
  현재 자료로 확정하지 못한 수식은 추가 분석 대상으로 남긴다.
- 색상 팁·지우기·색 혼합 브러시와의 상호 작용도 검증한다.

**예상 수정 위치:** `crates/io/src/sut/blend.rs`, `effector.rs`,
`crates/paint/src/brush.rs`, `dynamics.rs`, `render.rs`; 필요하면 CSP 색상 전용 모듈 추가.

**완료 조건**

- 잎 브러시 1/2/3에 서로 다른 주색·보조색을 지정했을 때 일정 혼합이 실제 획에 반영된다.
- 난수 0에서도 일정 효과는 유지되고, 기능 비활성화 시에는 적용되지 않는다.
- 획 단위 값은 획 도중 유지되고 팁 단위 값은 정의된 시점에 평가된다.
- 관련 11개 소재의 경고는 기능과 비교 검증이 완료된 경우에만 제거한다.
- ABR 색상 동작과 8/16/32비트 회귀 검사가 통과한다.

### BR-04. CSP 손떨림 보정 완성 및 후 보정

**사용자 재현 추가(2026-11-03):** `茂み1 2`(원본 `茂み1`, 크기 100)에서 CSP보다
선이 보정되며 따라오는 느낌이 보고됐다. 저장 프리셋은 손떨림 10, 속도 조절 off,
stickiness 4, 리본 quarterTurns 1이다. 확인한 Prism 화면의 상단 매끄럽게는 0%이고
실행 파일은 수정 후 빌드다. 현재 활성 브러시의 메모리 상태와 실제 입력 빈도는
아직 직접 계측하지 않았으므로, 저장값만으로 증상의 원인을 확정하지 않는다.

- 현재 필터에 일정 속도 600px/s의 합성 입력을 1초 공급하면 60/120/240Hz에서
  각각 75/37.5/18.75ms에 해당하는 위치 지연이 생긴다. 이는 샘플 빈도 의존성을
  확인한 실험이며 사용자의 실제 지연값 또는 CSP 대비 차이 측정이 아니다.
- `StrokeRenderer::tail_preview`는 매 갱신 시 generator를 복제해 `finish`를 호출하고,
  이때 CSP stabilizer의 펜 해제 따라잡기도 계산된다. 실제 pen-down 표시와 pen-up
  처리가 원본에서 어떻게 구분되는지 확인해야 한다. 근거 없이 보정을 끄거나
  필터 수치를 낮추는 방식으로 호환 완료 처리하지 않는다.
- 이 사례의 비교 검사는 raw 입력 빈도·타임스탬프, 필터 출력, 미리보기 갱신 시간,
  리본 처리 시간을 함께 기록해 입력 필터 지연과 렌더링 지연을 분리해야 한다.

**현재 상태:** CSP 전용 손떨림·속도 보정은 일부 구현되어 있다. 펜 해제 시 압력,
장치별 배율, 따라잡기 조기 종료는 미검증·미반영 부분이 있다. 후 보정은 별도 기능이며
22개 소재에서 미지원 경고가 나온다.

- `FlickerReduction`, 속도 보정 종류, `Stickness`와 입력 시간의 의미를 유지한다.
- `BrushUseRevision`/`BrushRevision` 및 연결 옵션을 조사하여 후 보정을 독립 구현한다.
- 후 보정의 적용 시점·대상, 필압·폭 보존, 모서리 처리, 시작·끝 효과와의 순서는
  원본 관찰·분석으로 정한다. Photoshop 매끄럽게 수치 증가로 대체하지 않는다.
- 종료 처리로 획을 다시 계산할 경우 이전 미리보기를 제거하고 정확히 한 번 합성한다.
- 획 취소·실행 취소·다시 실행은 한 획을 하나의 작업으로 취급한다.

**예상 수정 위치:** `crates/paint/src/csp_stabilizer.rs`, `dynamics.rs`, `render.rs`,
`crates/io/src/sut/blend.rs`, `crates/engine/src/brush_cmds.rs`.

**완료 조건:** 느린 선·빠른 선·모서리·정지·짧은 점·저필압 종료를 CSP와 비교한다.
보정 수준과 속도 보정 조합에 대한 테스트가 통과하고, 후 보정 활성 소재 22개를
재검사한다. 펜 해제 시 이중 합성·비정상 꼬리·실행 취소 잔상이 없어야 한다.

### BR-05. 입자 회전, 입력 곡선과 단위

- 입자 회전 입력을 고정 각도로 대체하는 경로를 수정한다. 현재 9개 소재가 영향받는다.
- 입자 크기 단위를 해석한다. 현재 6개 소재의 단위를 픽셀로 처리하고 있다.
- 브러시 크기 입력 제어 `0x40`의 의미와 평가 시점을 확인하고 적용한다.
- 픽셀·물리 단위·브러시 크기 비율은 각각 캔버스 DPI, 기준 크기에 따라 변환한다.
  화면 확대율에 연동하는 옵션과 물리 단위 변환을 혼동하지 않는다.
- 불명확한 단위·제어는 오류나 명시적 미지원으로 남기고 조용히 픽셀로 간주하지 않는다.

**예상 수정 위치:** `crates/io/src/sut/mod.rs`, `effector.rs`,
`crates/paint/src/csp_spray.rs`, `dynamics.rs`, 엔진의 문서 DPI 전달 경로.

**완료 조건:** DPI 72/300/600, 확대율 25/100/400%에서 단위별 기대 결과를 검사한다.
필압·기울기·방향·회전은 지원되는 입력별로 검증하며, 극단값에서 크기·입자 수·작업량을 제한한다.

### BR-06. CSP 색 혼합 방식

- 현재 일반 blending으로 근사하는 type 2(현재 5개 소재)를 원본 의미에 맞게 구현한다.
- type 1과 번짐·크기 연동 옵션도 조사하고 별도 상태를 기록한다.
- 색 혼합과 불투명도·알파·기존 캔버스 색·색상 팁·리본의 적용 순서를 확정한다.
- 혼합 종류별로 읽는 캔버스 영역과 갱신 시점을 명시하여 실시간/확정 획 결과를 맞춘다.

**예상 수정 위치:** `crates/io/src/sut/mod.rs`, `crates/paint/src/csp_mixing.rs`, `render.rs`.

**완료 조건:** 투명·흰색·유색 배경과 기존 획 위 반복 그리기를 CSP와 비교한다.
빈 레이어에서만 정상인 상태를 완료로 처리하지 않는다.

### BR-07. 이중 브러시

- 팁 자산 누락 2건과 렌더러 기능 부족을 별도 결함으로 추적한다.
- 자산 참조·캐시 해석을 조사한다. 실제 원본 자산이 없다면 임의의 팁으로 대체해
  정상이라고 표시하지 않고 누락 원인을 알린다.
- 이중 브러시의 필압·난수·회전·flow·간격·두께·텍스처·리본·팁 순서·반전·분사
  옵션을 목록화하고, 주 브러시와 별개 상태가 필요한 항목을 구현한다.
- 두 브러시의 영역 합성·마스킹과 색상 팁 처리의 추정 공식을 원본과 비교한다.

**예상 수정 위치:** `crates/io/src/sut/dual.rs`, 소재 참조 해석 경로,
`crates/paint/src/dynamics.rs`, `render.rs`, `csp_ribbon.rs`.

**완료 조건:** 두 팁의 크기·간격·회전을 독립 변경했을 때 기대 결과가 나오고,
주 팁 외부 영역 및 타일 경계에서도 누락·잘림이 없다. 자산 부족은 기능 미지원과
다른 진단으로 표시한다.

### BR-08. 수채 경계·텍스처·시작과 끝

- 수채 경계 단위의 픽셀 근사, 텍스처 농도 강조의 대비 근사, 시작·끝 fade type 2의

- 부분 구현된 기능은 단순히 경고가 사라졌다는 이유로 검증 완료로 바꾸지 않는다.

**예상 수정 위치:** `crates/io/src/sut/mod.rs`, `crates/paint/src/csp_water_edge.rs`,

### BR-09. 전체 옵션 편집과 에이전트 제어

- CSP 옵션 목록을 ‘읽음/보존/편집/실행/저장/원본 검증’ 열로 관리한다.
- 도구 속성에 노출된 옵션뿐 아니라 보조 도구 상세에 해당하는 옵션까지 목록화한다.
- 132개 소재의 알 수 없는 표시 ID를 수집·중복 제거해 의미를 조사한다.
  소재 개수를 누락 옵션 개수로 잘못 집계하지 않는다.
- 기존 방향 1060, 분사 켜기 1130처럼 값만 저장되는 컨트롤은 실제 엔진 반영까지 연결한다.
- 원본 계열에 맞는 보정 이름·범위·단위·활성 조건을 표시한다.
- 구현되지 않은 옵션은 사용자가 정상 작동한다고 오해하지 않게 상태를 알린다.
- 기존 `brush.sutSettings.set` 등 엔진 명령을 확장하고 조회 결과로 적용값과 지원 상태를

- 프리셋별 변경은 다른 프리셋을 오염시키지 않아야 한다.

**예상 수정 위치:** `crates/paint/src/sut.rs`, `sut_catalog.rs`,
`crates/ui-egui/src/sut_panel.rs`, `csp_tool_property.rs`,

**완료 조건:** 대표 옵션을 UI와 명령에서 각각 변경해 동일한 획 결과를 얻고,

## 6. 구현 제약과 품질 게이트

- Rust 전용, 네이티브 egui/eframe/wgpu 구조와 기존 crate 계층을 유지한다.
- 원본 분석은 허가된 로컬 읽기 전용 범위를 따른다. 사실·추론·미확인을 구분하고,
  REA Evidence와 직접 Ghidra 결과를 혼용하지 않는다. 독립 구현하며 원본 코드는 복사하지 않는다.
- 비트 깊이와 색상 모델은 런타임 데이터다. 공용 API를 u8/sRGB 전용으로 제한하지 않는다.
- 외부 입력은 검증하고 배열 접근·길이 계산·재귀·메모리·입자 수를 제한한다.
  비테스트 코드에 패닉·새 unsafe 경로를 추가하지 않는다.
- 고비용 계산은 타일과 변경 영역 중심으로 처리하며 프레임마다 전체 표면을 스캔하지 않는다.
- 핫 패스 변경은 24–36MP 문서의 release 측정과 전후 기록을 남긴다.

구현 변경마다 적용되는 저장소 검사:

```sh
cargo test -p <수정한-crate>
cargo clippy -p <수정한-crate> --all-targets -- -D warnings
cargo xtask layers
```

변경 내용에 따라 추가 실행한다.

```sh
# 명령 추가/변경
cargo test -p prism-engine --test panic_hunt -- --ignored
# 명령 추가 시 메뉴 목록 재생성
cargo xtask parity
# io 등 포맷·합성 관련 crate 수정
cargo xtask test-corpus
# 핫 패스 수정
cargo xtask perf --quick
# 측정 지표/체크리스트 변경
cargo xtask scorecard
# 사용자 로컬 소재 전체 검사
cargo test -p prism-engine --test csp_library_local every_local_csp_material_imports_and_paints -- --ignored --nocapture
```

테스트 프로세스의 성공만 확인하지 않고 결과 JSON의 오류·빈 획·경고·검사 제외 항목을
확인한다. 기준선이 개선되면 관련 문서와 devlog를 갱신하며 기존 실패는 새 회귀와 구분한다.
